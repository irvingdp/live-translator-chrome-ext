# 預讀模式優先使用上傳者的字幕軌

預讀模式透過**語音辨識**與**翻譯**把即將播放的音訊轉成**定時字幕**（ADR 0006）。許多影片本來就附有上傳者寫的定時字幕。這些句子比任何語音辨識的結果都好，而且不耗額度、不需要音訊。

因此在預讀模式中，當影片有講話語言的**字幕軌**時，預讀會從字幕軌讀取句子，略過語音辨識。如果還有目標語言的字幕軌，翻譯也從那條字幕軌取得，連翻譯也略過。沒有字幕軌時，一切照舊。這是自動進行的。自 issue #18 起，觀眾可以關閉它（「優先使用影片字幕軌」）；見「考慮過的選項」。

- **哪一條是原文字幕軌：** popup 來源語言那一條；來源語言設為自動偵測時，則是講話語言那一條。YouTube 沒有欄位標示講話語言，但它自己的語音辨識字幕軌就是這個語言；一般影片則以 `default` 字幕軌代替。兩者都沒有時，就沒有原文字幕軌。
- **目標語言字幕軌只有在有原文字幕軌時才算數。** 只有目標語言字幕軌時，語音辨識與翻譯照舊執行：辨識出的句子和上傳者的字幕切法不同，無法配對。
- **有原文字幕軌但沒有目標語言字幕軌時，** 不論語音辨識設定為何，都由翻譯（Chrome 內建 Translator，再來是 Google 網頁翻譯）處理，不使用 Gemini 的額度。
- **句子：** 連續的字幕會合併到句末標點為止；沒有句末標點時，在 15 秒或超過 2 秒的空白處切開。一個句子的翻譯是與它重疊最多的目標語言字幕，依序排列，每則只使用一次。
- **時機：** 每支影片只決定一次，包含 YouTube 的站內換頁。預讀最多等字幕軌 2 秒，期間以「讀取字幕中…」讓播放器讀取等待，等不到就在這支影片剩下的部分使用語音辨識。使用字幕軌時不讀取音訊，所以跳轉後字幕會立刻出現。翻譯仍然最多提前 30 秒，一次一批。

## 如何讀取 YouTube 字幕軌

YouTube 的字幕網址現在通常需要播放器計算出來的來源證明 token（`pot`）。自己去抓那些網址，或自己產生那個 token，都等於規避 YouTube 的限制，這個擴充功能不這麼做。做法是：

1. 擴充功能透過 YouTube 播放器自己的 API 打開字幕。
2. 在頁面中讀取播放器自己下載的回應，就像緩衝擷取讀取音訊那樣。
3. 用 CSS 隱藏 YouTube 自己的字幕顯示，避免兩者重疊。

字幕軌下載後會在這支影片剩下的時間內保留，不論觀眾之後怎麼按 CC 按鈕。停止字幕時，會把 CC 狀態恢復成之前的樣子，並取消隱藏 YouTube 的字幕。

一般 HTML5 影片則透過 `video.textTracks` 讀取 `<track>` 元素。頁面讀不到的字幕軌（來自其他來源且沒有 CORS）視為不存在。

## 考慮過的選項

- **把 YouTube 自動產生的字幕當原文字幕軌：** 否決。它們大多沒有標點，句子只能在停頓處切，翻譯效果差。Gemini 和 Whisper 會加標點，所以這類影片交給語音辨識。
- **把 YouTube 的自動翻譯（`tlang`）當翻譯：** 使用者否決。只有上傳者以目標語言寫的字幕軌才會取代翻譯。
- **語音辨識為 Gemini 時，讓 Gemini 翻譯字幕軌的文字：** 否決。這仍會耗用 ADR 0006 想要避開的每天 500 次額度；裝置端翻譯不花任何成本。
- **提供關閉字幕軌的設定：** 一開始沒有。它在逐字標示時加入（issue #18）：字幕軌沒有逐字時間，想要逐字標示的觀眾必須能選擇改用 Whisper。popup 有「優先使用影片字幕軌」（預設開啟）。開啟逐字標示時，提示會顯示「使用 YouTube 字幕（不支援逐字標示）」並附「改用語音辨識」按鈕，按下後關閉此設定，並從觀眾所在位置以語音辨識重新開始。
- **直接抓取 `timedtext` 網址：** 否決；見上文。

## 後果

- 2026-11-17 在真實 Chrome 驗證（TED "Grit"，373 秒）：自己抓取字幕軌列出的網址會得到空內容。執行 `setOption('captions', 'track', …)` 後，播放器會用一次 XMLHttpRequest 下載整條字幕軌（`fmt=json3`，帶有 token），由 MAIN world 的 hook 讀取，約 20 毫秒。選擇已經在顯示的字幕軌不會下載任何東西，所以那條要重新載入（`setOption('captions', 'reload', true)`）。`setOption('captions', 'track', {})` 會關閉字幕，「關閉」狀態就是這樣恢復的。
- 觀眾原本的字幕軌在下載完成後立刻恢復，而不是等到停止時：字幕執行期間 YouTube 的字幕顯示一直是隱藏的，所以觀眾看不到切換。
- 串流的一般影片（`blob:` 來源）原本預讀讀不到音訊，現在只要有可讀取的字幕軌就能使用。
- 語音辨識為 Gemini 時，需要翻譯的字幕軌會使用 Chrome 的翻譯與 Google 網頁翻譯。Google 的網域只有在選擇 Whisper 語音辨識時才會授權，所以沒有授權時，Chrome 無法翻譯的語言組合會以「翻譯失敗」結束。為此，popup 在每次開始預讀時都會開始下載 Chrome 的語言包。
- 即時模式不變：它翻譯的是當下聽到的內容，用不到預先的定時字幕。
