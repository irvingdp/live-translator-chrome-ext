# 預讀翻譯可選用 Groq 的 Qwen

語音辨識是 Whisper 時，預讀的翻譯原本固定交給 Chrome 內建的 Translator，它不行時再改用 Google 網頁翻譯（[ADR 0006](0006-預讀的語音辨識與翻譯分開選擇.md)）。用字幕軌、但沒有目標語言字幕軌時也一樣（[ADR 0007](0007-預讀優先使用上傳者的字幕軌.md)）。Chrome 的 Translator 一次只翻一句，看不到上下文，所以常照字面翻，有時連意思都翻錯。2026-11-21 用一段 TED 演講測試，它把「stratospheric IQ scores」翻成「平流層智商分數」，把「quizzes and tests」翻成「測驗和測驗」，第一句的意思也翻錯了。

因此，語音辨識是 Whisper 時，觀眾可以在 popup 選擇翻譯服務（issue #29）：

- **Chrome 內建翻譯**：預設，跟以前一樣，它不行時再改用 Google 網頁翻譯。
- **Groq（Qwen）**：Groq 上的 `qwen/qwen3.8-27b` 語言模型。每個片段的句子一次送出，並附上前一段最後兩句當上下文。它會照意思翻成語、用語前後一致，也會用目標語言的地區用法（繁體中文用台灣的說法）。

它用的是觀眾已經有的 Groq 金鑰，也就是 Groq Whisper 那一把，所以不用新註冊帳號。這就是 ADR 0006 否決 DeepL 和 Microsoft、卻接受它的原因。它的額度和 Groq Whisper 分開算。模型寫死在程式裡，觀眾不能選，跟預讀用的 Gemini 模型一樣。Gemini 語音辨識本身就會翻譯，所以選 Gemini 時沒有這個選項。

**失敗時：** Groq（Qwen）翻不了的片段，只有那個片段改用 Chrome 內建翻譯，字幕上會短暫提示，觀眾的選擇不變。原因可能是逾時、限流、服務出錯、回覆無法解析，或時間預算不夠。每日額度用完或金鑰被拒時，這次預讀剩下的片段都直接用 Chrome 翻譯，不再等 Groq 失敗。碰到每分鐘上限時（開始或跳轉後一次送出好幾個片段），接下來 20 秒都直接用 Chrome 翻譯，之後再試 Groq。每個片段的頁面預算仍然是 8.5 秒：Groq 最多 4.5 秒，而且一定要留 3 秒給 Chrome 翻譯。

## 考慮過的選項

這些選項都在 2026-11-21 測過。測試用的是同一段 TED 演講的前 18 句（英文翻繁體中文，要求台灣用語），一次送出：

- **Groq `qwen/qwen3.8-27b`（`reasoning_effort: "none"`）：** 採用。每次 1.0–1.9 秒，品質最好：「decimals」翻成「小數」，「drop out」翻成「中途退學」，「West Point」翻成「西點軍校」。
- **Groq `openai/gpt-oss-120b`：** 否決。1.4–1.6 秒，但把「decimals」翻成「十進位」，憑空多出「小平行四邊形」，有一次把「drop out」翻成「退伍」。`gpt-oss-20b` 比較快（0.9–1.0 秒），但用詞比較生硬。
- **Gemini API 上的 Gemma 4（`gemma-4-26b-a4b-it`、`gemma-4-31b-it`）：** 否決。品質好，額度和 Gemini 分開算，也用同一把 Gemini 金鑰。但預設會先「思考」，18 句要 56 秒；改成 `thinkingLevel: "minimal"` 後約 1.7 秒。問題是 15 次請求有 14 次回 503（需求量過高），免費額度下幾乎拿不到服務。
- **Chrome Prompt API（Gemini Nano）：** 否決。它不需要金鑰，但 Chrome 157 不支援中文輸出：`availability` 回傳 `unavailable`，`create` 會丟出 `NotSupportedError`。不指定語言時，它還是會用中文回答，但意思會錯，例如把「gave out homework」翻成「批改作業」，句子也會亂序。18 句要 12.3 秒。它還需要 22 GB 的磁碟空間。
- **DeepL、Microsoft Translator：** 維持 ADR 0006 的否決，因為都要多註冊一個帳號。
- **一次只翻一句：** 否決。一個片段一次請求，比較省額度，模型也看得到整段。
- **要求回傳 JSON 陣列：** 否決。2026-11-22 實際使用時（韓語綜藝節目），模型常把重複的句子或很短的語氣詞合併或略過，句數對不上，整個片段都變成無法解析的回覆。改成每句加上編號，送出 `{"1": …, "2": …}`，要求照同樣的編號回覆後，同樣的 14 個片段都解析成功。

## 後果

- Groq 的免費額度是每個模型每天 1,000 次、每分鐘 8,000 tokens。一個片段約 15 秒，連同上下文約 300–400 tokens，所以每天大約能翻 4 小時的影片。實測一個 7 句的片段，連同上下文約 370 tokens。開始或跳轉後一次送出好幾個片段時，仍可能碰到每分鐘上限，這時會暫停 Groq 20 秒，這段期間改用 Chrome 翻譯。
- 選 Groq（Qwen）時，這些文字會送到 Groq：辨識出的句子，或字幕軌的句子，加上前兩句的原文和譯文。音訊不會送過去。`PRIVACY.md` 和商店說明都寫了這一點。本地 Whisper 搭配 Groq（Qwen）時，也需要 Groq 金鑰和 `api.groq.com` 的權限。
- 翻譯的順序（Groq（Qwen）、Chrome 內建翻譯、Google 網頁翻譯）和時間預算的計算，抽成了頁面的獨立模組，有自己的測試。
- 如果 Groq 下架這個模型，要改程式換模型，並重新量品質和速度。
