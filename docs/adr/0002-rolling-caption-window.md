# 字幕改為兩個單位的捲動視窗

> **部分已被取代。** 切分單位的 `CaptionChunker` 與 `TranscriptStabilizer` 隨 1.5.0 移除 Deepgram（#10）一起拿掉。捲動視窗（`CaptionWindow`）、推入動畫與外觀設定仍在使用，Gemini 即時模式的列切法見 [ADR 0004](0004-gemini-live-translate-as-a-combined-provider.md)。

原本字幕一次只顯示一個 Deepgram 段落。一個段落是一整句話，文字一直變長到講者停頓為止：原文換成五行以上、翻譯兩到三行，字幕框蓋住影片一大塊。翻譯又是按段落累積、整串重送，所以每出現一個穩定的詞組，DeepL 就要把整段重翻一次。

2026-08-05 起，字幕改為由兩個**顯示單位**組成的捲動視窗。每個單位是一行原文加一行翻譯，畫面上共四行。新單位到達時，最舊的單位從上方離開，另一個以動畫往上滑。

- **切分在背景進行**，不是在 content script：一個單位的翻譯必須正好對應一個原文單位，而翻好的中文無法在頁面中再切回與原文對齊的片段。資料流是 Deepgram → `TranscriptStabilizer`（穩定文字）→ `CaptionChunker`（顯示單位）→ `CaptionWindow`（最後兩個單位）→ `CAPTION_WINDOW` 訊息 → `CaptionOverlay`。
- **切分規則**依序是：句末標點（`.`、`?`、`!`、`。`、`！`、`？`、`…`，收尾引號與括號跟著前一句）；過寬時在子句標點切；仍過寬時在上限前最後一個字詞邊界切，沒有空白就直接切；最後只在同一句內貪婪合併相鄰片段。ASCII 的 `.` 只有後面接空白或結尾時才算句末，避免把 `$3.5`、`example.com`、`U.S.` 切碎。
- **寬度是視覺估計**：中日韓、全形、假名算 2，其他算 1，以 code point 迭代。上限是 `maxLineWidth` 設定（40–140）。
- **已關閉單位的文字凍結**：邊界只從穩定文字計算，chunker 保存自己凍結的文字，絕不從重新計算的結果重讀；重新計算的單位數變少時（調寬行寬、最終文字比暫時文字短），什麼都不重開。單位 id 是 `<segmentId>#<index>`。
- **進行中的單位**顯示原始暫時文字的剩餘部分（第三行逐字變長），翻譯只翻其中穩定的部分（第四行先填上再修正）。來不及確認又沒有標點時，可能短暫換成五行；寧可換行也不用刪節號，內容永遠不丟。
- **訊息**：`CAPTION_ORIGINAL` 與 `CAPTION_TRANSLATION` 換成一個帶有整個視窗的 `CAPTION_WINDOW`。背景擁有視窗狀態，每次變更都送完整視窗；內容只有幾百位元組且冪等，順序錯亂的翻譯不會弄壞畫面，content script 重新注入後的重播也只是再送一次。
- **推入動畫**：軌道底部對齊。視窗已滿時，先新增單位、立刻以無動畫的 `translateY` 抵銷跳動、下一個影格再以 transition 清除，`transitionend` 時移除最舊的單位。從一個單位變兩個只是框變高。`prefers-reduced-motion: reduce` 略過動畫。
- **外觀設定**：新增 `maxLineWidth`（40–140，預設 90）、`backgroundOpacity`（0–100，預設 78）、`bottomOffset`（影片高度的 0–60%，預設 8，避開 YouTube 控制列），popup 加三個滑桿，session 中也能調。外觀經由 `chrome.storage.onChanged` 即時套用，不新增訊息；`CaptionOverlay` 只接收 `CaptionAppearance`，不碰 storage。

## 考慮過的選項

- **自動縮小字型，把文字擠成一行：** 不做。
- **用刪節號截斷：** 否決，內容永遠不能丟。
- **在 content script 切分：** 否決，翻譯無法切回與原文對齊的片段。
- **寬度改變時重設段落：** 否決。單位 id 含索引，重新從 0 開始會讓已在畫面上的 id 換成不同的文字。
- **寫死縮寫清單**（讓 `Mr. Smith` 不被切開）：刻意不在範圍內。
- **水平位置控制或拖曳移動：** 不做，只有垂直偏移。

## 後果

- 每個顯示單位分別翻譯，每個 DeepL 請求都很小。
- 已關閉的邊界在寬度 40、60、90、140 驗證過是穩定的，但大約 30 欄以下可證明會失敗，所以 `maxLineWidth` 的下限 40 是承重的，不只是易用性。chunker 不依賴這個穩定性，因為它保存自己凍結的文字。
- 翻譯始終沒到的單位，翻譯行保持空白，原文照常顯示、往上捲。session 錯誤訊息與 `translation_disabled` 狀態不變，狀態行在視窗下方，不受動畫影響。
- 單純的 video 元素全螢幕時，原生 `VTTCue` 備援把同一個視窗渲染成最多四行加狀態行。
